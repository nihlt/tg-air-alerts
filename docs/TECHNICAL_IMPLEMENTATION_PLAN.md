# Етап 3. Event System

## Ціль

Перейти від повідомлень до подій.

---

## Структура події

```json
{
  "event_id": "",
  "created_at": "",
  "updated_at": "",
  "messages": []
}
```

---

## Життєвий цикл події

### Створення

Нове повідомлення не схоже на існуючі події.

↓

створюємо нову подію.

### Оновлення

Нове повідомлення схоже на існуючу подію.

↓

додаємо його до події.

### Завершення

Подія не оновлювалася певний час.

↓

архівуємо.

---

## Питання для дослідження

* через скільки хвилин завершувати подію;
* як поводитися при зміні маршруту;
* як обробляти уточнення.

---

# Definition of Success

Система успішна, якщо:

1. Збирає повідомлення без втрат.
2. Групує більшість дублікатів в одну подію.
3. Значно зменшує кількість сповіщень.
4. Дає користувачу короткий і зрозумілий результат.
5. Не потребує ручного аналізу десятків Telegram-каналів.
